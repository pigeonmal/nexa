# Language design decisions

Nexa borrows useful ideas from Kotlin and Swift, but keeps one source language and one typed IR. Syntax is selected for cross-platform clarity; Swift and Kotlin spelling differences are handled by the backends. Features enter the language when their type and runtime behavior are defined well enough to generate direct native code.

| Concept | Decision | Nexa design and status |
| --- | --- | --- |
| Condition (`if / else`) | Integrate now | Lowers directly to native branches for UI and event actions. |
| Platform-specific UI | Integrate now | `platform ios { ... }` and `platform android { ... }` are selected during target lowering; inactive widgets never reach the target IR. |
| Status bar | Integrate first slice | An app- or screen-level `StatusBar(style: Default|Light|Dark, hidden: true|false, background: "#RRGGBB")` declaration lowers to native SwiftUI safe-area and AndroidX window status-bar APIs. Animated transitions remain deferred. |
| Bottom sheet | Integrate first slice | `BottomSheet(isPresented: ..., partial: true|false)` lowers to SwiftUI `.sheet` with native presentation detents or Compose Material 3 `ModalBottomSheet` with a partially expanded state; custom snap points and transitions remain deferred. |
| Refresh control | Integrate first slice | `RefreshControl` lowers to SwiftUI `.refreshable` and Compose Material 3 `PullToRefreshBox`; custom indicators and event streams remain deferred. |
| Application bottom bar | Integrate first slice | `AppBottomBar(selected: ...)` lowers to SwiftUI `TabView(selection:)` and Compose Material 3 `Scaffold`/`NavigationBar`; static labels, optional native icon names, static badges, and unique `Int32` tab indexes are supported. iOS uses SF Symbols and native tab badges; Android uses drawable resources with a remembered lookup and transparent fallback plus Material 3 `BadgedBox`; custom transitions remain deferred. |
| Linking | Integrate first slice | `Link(url: ...)` accepts typed `String` expressions, validates literal schemes at compile time, and lowers dynamic values to SwiftUI `Link` or an Android `ACTION_VIEW` intent with native handler checking. Incoming links, URL availability expressions, and universal-link routing remain deferred. |
| Accessibility | Integrate first slice | `Accessibility(label: ..., role: ...)` accepts typed `String` expressions and lowers to Swift accessibility modifiers and Compose semantics, including native heading semantics. Hints, focus control, and custom actions remain deferred. |
| RTL / LTR direction | Integrate first slice | `Direction(value: LTR|RTL)` applies a static native layout direction at the app root; dynamic locale changes and directional spacing APIs remain deferred. |
| Lifecycle callbacks | Integrate first slice | One top-level `OnAppear { ... }` and `OnDisappear { ... }` block is supported on the app body and named screens, lowering directly to SwiftUI lifecycle modifiers or Compose `LaunchedEffect(Unit)`/`DisposableEffect(Unit)`; app background events remain deferred. |
| Text weight and metrics | Integrate first slice | `Text` maps `fontWeight`, `lineLimit`, `lineHeight`, `letterSpacing`, and `selectable` directly to SwiftUI modifiers and Compose native selection; custom text layout and nested spans remain deferred. |
| Button icon and loading state | Integrate first slice | `Button(..., icon: "name", loading: Bool)` maps a static name to an SF Symbol on iOS or a drawable resolved once on Android, then emits a native progress indicator and disables the control while loading; omitting both keeps the direct minimal button path. |
| Button disabled state | Integrate first slice | `Button(..., disabled: Bool)` maps directly to SwiftUI `.disabled` or Compose `enabled = !disabled`; when combined with loading, the generated native condition is folded into one enabled/disabled expression. |
| Pressable interaction | Integrate first slice | `Pressable(disabled: Bool, haptic: Light|Medium|Heavy) { ... }.onPress { ... }.onLongPress { ... }` lowers dynamic disabled state and optional static native haptic feedback directly to SwiftUI/UIKit or Compose. Named modifiers make tap and long-press actions explicit; hover, focus, pressed-state styling, and custom accessibility actions remain deferred. |
| Text input focus, submit, and length | Integrate first slice | An optional mutable `focused: Bool` binding lowers to SwiftUI `@FocusState`/`.focused` or Compose `FocusRequester`/`onFocusChanged`; an action block lowers to `.onSubmit` or `KeyboardActions` with a native Done IME action; `maxLength` is a positive integer literal enforced by the native input callback. Selection, autofill, and richer validation remain deferred. |
| Keyboard-aware scrolling | Integrate first slice | `KeyboardAware(dismiss: Interactive|Never)` uses native SwiftUI keyboard dismissal and Compose IME inset/nested-scroll APIs. The static mode is validated at compile time; keyboard height/events and explicit focus scrolling remain deferred. |
| Layout borders | Integrate first slice | `borderColor` and `borderWidth` are typed static layout style values. Swift emits a `RoundedRectangle` overlay stroke and Compose emits `Modifier.border`; incomplete pairs are rejected at compile time. |
| Overlay stack | Integrate first slice | `Stack { ... }` maps to SwiftUI `ZStack` or Compose `Box`, preserving source order and native alignment/modifier handling without a shared layout engine. |
| Horizontal virtualized lists | Integrate first slice | `FastList(rows, axis: Horizontal, key: .self) { row, index in ... }` maps to iOS `UICollectionView` with horizontal flow layout and Android `LazyRow`; the default vertical path remains `UITableView`/`LazyColumn`, with direct scalar keys and no intermediate row collection. |
| Grid virtualized lists | Integrate first slice | `FastList(rows, axis: Grid(columns), key: .self) { row, index in ... }` validates a positive static column count and maps to an iOS compositional `UICollectionView` grid or Android `LazyVerticalGrid`, preserving direct scalar keys and native virtualization. |
| Fixed virtualized-list sizing | Integrate first slice | `FastList(rows, rowHeight: positiveLiteral) { row, index in ... }` applies static row or cell sizing directly to UIKit and Compose virtualization; omitting `rowHeight` keeps dynamic native sizing. |
| Virtualized-list pagination | Integrate first slice | The `.onEndReached { ... }` modifier maps to native scroll-end observation on UIKit and Compose, fires once per source count, and re-arms after the collection grows. |
| FastList pull-to-refresh | Integrate first slice | A direct `FastList` child of `RefreshControl` attaches `UIRefreshControl` to UIKit lists or wraps the Compose lazy list in `PullToRefreshBox`, preserving the native virtualized path. |
| FastList scroll position | Integrate first slice | `scrollPosition: Int32` tracks the first visible native row/item and applies external changes through UIKit scroll APIs or Compose `LazyListState`/`LazyGridState`; no cross-platform scroll registry is introduced. |
| FastList scroll events | Integrate first slice | The `.onScroll { ... }` modifier runs once when the first visible row/item changes, using UIKit delegate callbacks or Compose lazy state observation without per-pixel action dispatch. |
| FastList sticky headers | Integrate first slice | The `.stickyHeader { ... }` modifier is restricted to vertical lists and maps to a pinned `UITableView` section header or Compose `stickyHeader`; horizontal and grid lists are rejected during semantic lowering. |
| FastList sectioned data | Integrate first slice | `FastList(sections: groups, key: .self) { item, index, section in ... }.sectionHeader { ... }` maps to native `UITableView` sections or direct nested `LazyColumn` iteration. The compiler preserves section/index/item bindings and rejects flattening-sensitive scroll, pagination, and ordinary sticky-header options until their section semantics are defined. |
| Layout size bounds | Integrate first slice | `minWidth`, `maxWidth`, `minHeight`, and `maxHeight` are non-negative static dimensions. Inverted pairs are rejected at compile time; Swift emits native frame bounds and Compose emits `widthIn`/`heightIn` without a shared layout runtime. |
| Responsive size predicates | Integrate first slice | `Layout.isRegularWidth`, `isCompactWidth`, `isRegularHeight`, and `isCompactHeight` lower to native Swift size classes or Compose configuration dimensions and remain ordinary typed `Bool` expressions. No wrapper layout or shared measurement pass is introduced. |
| Layout animation | Integrate first slice | A static `animation: Spring|EaseIn|EaseOut|EaseInOut|Linear` layout option lowers to SwiftUI animation and Compose `animateContentSize` with native specs. No shared frame scheduler is introduced; transforms, transitions, and gesture-driven animations remain deferred. |
| Network, paths, and files | Integrate native library now | `Network.fetch`/`download`, `Path`, and `File` qualified calls are checked during compilation and map directly to URLSession on iOS or Play Services Cronet and native file APIs on Android. Request options, cache policy, redirects, byte limits, optional pinning, and asynchronous file operations stay platform-native; typed error values remain future work. |
| Multiple choice (`when / switch`) | Integrate first slice | Exhaustive scalar `when` with literal or closed-enum cases and a required `else` lowers directly to Kotlin `when` or Swift `switch`; associated-value patterns remain deferred. |
| AND / OR / NOT | Integrate now | `&&`, `||`, `!`; native short-circuit operators. |
| Equality and comparison | Integrate now | `==`, `!=` for scalar, enum, optional, recursively equatable collection, pair/triple, and non-empty value-struct types; numeric `<`, `<=`, `>`, `>=`. Exact types are required; no runtime conversions. |
| Mutable variable / constant | Keep Nexa terms | `state` means observed, mutable UI state and `let` means immutable. Both can infer a type from a non-empty initializer using shared defaults (`Int32` for integer literals and `Float64` for decimal literals); explicit annotations remain available for narrower numeric bindings. `var`/`val` aliases would add duplicate syntax. |
| Function / return | Integrate first slice | App-local functions require explicit parameter and return types, ordered immutable `let` locals, and exactly one return expression. Calls are checked at compile time and lower to direct private top-level Swift/Kotlin functions; `async fn`, direct `await`, async lifecycle actions, and native network/file calls are integrated with Swift `async`/`.task` and Kotlin `suspend`/`LaunchedEffect`. Closures, generics, and dynamic dispatch remain deferred. |
| Async / await | Integrate first slice | `async fn`, direct app calls, and qualified native calls use native Swift `async`/`.task` or Kotlin `suspend`/`LaunchedEffect(Unit)`. No Nexa scheduler or boxed future crosses the generated code. Typed error values and richer cancellation remain deferred. |
| Nullable / optional | Integrate first slice | Explicit `T?` and `null` lower directly to Swift optionals and Kotlin nullable types. Pair/Triple and value-struct members plus optional collection indexing (`value?[index]`) lower to native optional chaining; forced unwrap operators and reference-type members remain deferred. |
| Default value if null | Integrate first slice | Nexa uses `??` and lowers to Swift `??` or Kotlin `?:` while preserving native short-circuit evaluation. |
| Safe access | Integrate first slice | `?.` with compile-time member/type checking for optional Pair, Triple, and value-struct members. Lower directly to native optional chaining; forced unwraps remain deferred. |
| Loops | Integrate first slice | Action blocks support direct native `for item in array/set`, `for (key, value) in map`, `for item in start..end`, positive literal `step` ranges, and `while condition` control flow. `..` is inclusive and `..<` is exclusive; range bounds remain native without array materialization. `break` and `continue` are checked to stay inside loops; all loop bindings are immutable. Loops in pure functions remain deferred, and UI collections should use `FastList` so large lists stay virtualized. |
| `break` / `continue` | Adopt with loops | Direct loop control, validated by the parser/type checker. |
| Range | Integrate first slice | `start..end` and `start..<end` are lowered as compact native ranges in action loops. `start..end step positiveInt32Literal` uses Swift `stride` or Kotlin `step` without materializing an array; dynamic steps and range expressions outside `for` remain deferred. |
| Anonymous function / closure | Integrate first slice | Inline closures are accepted only by `Array<T>` collection transformations. They are checked as non-escaping callbacks and emitted as native Swift/Kotlin lambdas; general closure values remain deferred, while captured bindings stay direct native references. |
| `map / filter / reduce` | Integrate first slice | Inline closures over `Array<T>` are typed in the compiler and lower directly to Swift `map`/`filter`/`reduce` and Kotlin `map`/`filter`/`fold`; closure capture and transform fusion remain future optimization work. |
| Array / List | Integrated | `Array<T>` lowers to Swift `Array<T>` and Kotlin read-only `List<T>` for immutable values. Mutable array states use Swift `Array<T>` or Compose `SnapshotStateList<T>` storage; `items.append(value)` and `items.remove(index)` lower to direct native mutation with an `Int32` index. |
| Dictionary / Map | Lookup, membership, and destructuring iteration integrated | `Map<K, V>` lowers to Swift `Dictionary<K, V>` and Kotlin read-only `Map<K, V>` for immutable values. Mutable map states use native Swift dictionaries or Compose `SnapshotStateMap<K, V>` storage. Keys are scalar `String`, `Bool`, or numeric values; map literals use last-value-wins for duplicate keys. `map[key]` returns `V?` through direct native lookup, `key in map` checks native key membership, `prices.set(key, value)` and `prices.remove(key)` mutate in place, and `for (key, value) in map` lowers to direct native dictionary/map iteration. |
| Set | Value, membership, and action iteration integrated | `Set<T>` lowers to native Swift/Kotlin set storage. Elements are scalar `String`, `Bool`, or numeric values; literals deduplicate, iteration order is unspecified, scalar `value in set` lowers to native membership, `tags.insert(value)` and `tags.remove(value)` mutate in place, and action `for` loops iterate the set directly. Kotlin mutable states use Compose `SnapshotStateSet<T>` so updates recompose without collection rebuilding. |
| Struct | Value construction and member access integrated | Top-level `struct User { id: Int64, name: String }` declarations are compile-time value types. Positional `User(42, "Ada")` construction lowers to a direct Swift struct initializer or Kotlin data-class constructor; `user.name` and optional `user?.name` are checked in the shared IR and emitted as direct native member access. Recursive value structs, named constructor arguments, methods, inheritance, and mutation remain deferred. |
| Pair / Triple | Value and field access integrated | `Pair<A, B>` and `Triple<A, B, C>` lower to Swift tuples and Kotlin `Pair`/`Triple` values. `.first`, `.second`, and `.third` are type-checked and lower to tuple positions or standard-library fields. |
| Permissions | Integrate config, status, and request slices | Generated projects contain a typed `nexa.config.nx` with permission purpose messages. The CLI validates it and emits iOS `Info.plist` and Android manifest metadata; permissions are configured only in that project file. `await Permissions.status(permission: Camera)` returns a typed native status, and `await Permissions.request(permission: Camera)` invokes the native authorization flow and returns the resulting status; denial recovery and rationale UI remain deferred. |
| Plugin package and IDL | Integrate typed boundary and config | `nexa plugin init` creates an isolated manifest, `interfaces.nxid`, and iOS/Android source boundaries. `nexa plugin check` validates typed interfaces and compile-time scalar config options; `nexa plugin generate` emits direct Swift/Kotlin binding skeletons. A local app can declare `plugin "path" as Namespace` and call its typed methods; the compiler resolves those calls statically and generated projects include the plugin's conventional platform source trees plus validated `nexa.config.nx` values. Dependency installation, version resolution, generated implementation methods, and typed error recovery remain deferred. |
| Class | Limit to identity cases | Prefer value types for ordinary models. Add references only where stable key or native handles require them. |
| Constructor | Adopt with value types | Struct constructors are positional and compile-time checked. They lower directly to Swift initializers or Kotlin data-class constructors, with no helper registry, boxed value layer, or dynamic dispatch. |
| Inheritance | Avoid in core | Use composition and statically dispatched interfaces; class inheritance brings dynamic dispatch and fragile shared behavior. |
| Interface / protocol | Adopt as static constraints | Resolve implementations statically where possible; avoid implicit existential boxes in hot paths. |
| Enum | Integrate first slice | Closed, typed `enum Name { caseA, caseB }` declarations and `Name.caseA` values lower to private Swift enums or Kotlin enum classes; scalar `when` accepts enum cases with a required `else`. Associated values and payload patterns remain deferred. |
| Extension | Defer as syntax sugar | Can desugar at compile time, but requires clear member lookup and conflict rules. |
| Generics | Adopt with monomorphization | Specialize statically to avoid runtime generic dispatch; track binary-size growth. |
| Type check (`is`) | Avoid general runtime checks | Prefer exhaustive matching on closed enums; no dynamic object hierarchy is planned for ordinary app models. |
| Type cast (`as / as?`) | Avoid unchecked casts | Add only explicit, type-checked conversions or optional casts when a real interop case needs them. |
| Exceptions | Prefer typed errors | Model recoverable cross-platform failures with `Result<T, E>`/typed effects; catch platform exceptions at native/plugin boundaries. |
| Access control | Adopt with modules | Enforce visibility at compile time; imports and namespaces need explicit module semantics first. |
| String interpolation | Integrate now | `$name` and `\(expression)` lower into typed native Swift/Kotlin string interpolation. Embedded expressions use the normal expression checker and do not allocate a template object. |
| Getter / setter | Defer | Computed properties can hide work or state changes; begin with explicit functions and state bindings, then add visible compile-time accessors if needed. |

The current operator and conditional syntax is demonstrated in [conditional-logic.nx](../examples/conditional-logic.nx). Component-local state, multi-file imports, content slots, and component navigation are described in the [language guide](language.md), with runnable examples in [custom-component-slot.nx](../examples/custom-component-slot.nx) and [custom-component-navigation.nx](../examples/custom-component-navigation.nx). This decision table is a design direction, not a claim that deferred features already compile.
